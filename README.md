# ギャンブル金庫タイム！

公開版: https://vault-break.vault-break.workers.dev/

Game StudioのPhaser構成で作った、2〜8人のターン制ブラウザカードゲーム。Node.js 22以上が必要です。

1. このフォルダーで `node server.mjs` を実行。
2. `http://localhost:4173` を開く。
3. 名前を入力し「CPUとプレイ」の開始ボタンでCPU戦、または「部屋を作成」で対人戦。

同じPCの別ブラウザ、または同じネットワークの端末から参加できます。別端末ではホストPCのLANアドレス（例：`http://192.168.1.20:4173`）を開き、部屋コードを入力してください。localhostの招待リンクは別端末では使えません。接続にはOSのファイアウォールで許可が必要な場合があります。インターネット越しの公開URLは未設定です。

## ルール

Aさん→Bさんの順に、1人ずつ探索／脱出を20秒で選びます。お宝は手番の人の未確保Gに加算され、脱出時に50G追加。警報は全員共通で、合計3個以上で残った人の未確保Gがゼロになります。確保済みの得点は減りません。

1〜10回目は小型金庫、11〜15回目は中型金庫、16回目以降は大型金庫をずっと探索します。次の強盗ラウンドでは小型金庫に戻ります。金庫のサイズ・形・素材・背景・進行表示が切り替わり、小型はコンビニ、中型は銀行、大型は大銀行のぼかした背景です。ダイヤルがじりじり回り、扉が開いてお宝が現れます。効果音ON時はクリック音も鳴ります。動きを減らすOS設定では演出を省略します。警報が出た回も探索回数に含み、同じ強盗中の警報は金庫を移っても引き継ぎます。

各回独立の抽選です。通報率は最初1%。小型は1回ごとに+2、中型は+3、大型は+1パーセントポイント上がり、上限70%。通常36種類・レア以上24種類の計60種類。DPRは大型金庫でのみ0.1%で、現在はブルーダイヤ200Gが対象です。

## 構成と検証

- `engine.mjs`：描画から独立したゲームルール。
- `server.mjs`：Node標準HTTP、部屋・CPU・WebSocket同期。サーバーが手番、選択、得点、共通警報を管理します。
- `public/`：DOM操作UIとPhaserの報酬演出。金庫をCSS、お宝をSVGで描画。Phaser 3.90.0（MIT）を同梱。フォントのみGoogle Fontsを使用し、未接続時はOSフォントにフォールバック。
- `node --test`：順番制・個別の未確保G・共通警報・DPR抽選・2/8人5ラウンドを検証。

部屋はメモリ保存です。サーバー再起動で消えます。タブ内の認証情報はsessionStorageに保存され、同じタブの再読み込みで復帰します。ホスト不在時の引き継ぎや永続保存は試作の範囲外です。サーバーはLAN対戦用に `0.0.0.0:4173` で待ち受けます。公開運用にはHTTPS対応のNodeホスティング等が必要です。

背景3種類はbuilt-in image_genで生成し、`public/assets/` に保存しています。生成プロンプトと保存先は [ASSETS.md](ASSETS.md)。`qa/safe-playthrough.mjs` はブラウザ確認専用の乱数固定プリロードです。通常の起動では読み込みません。

ホームは平面的なゲームランチャー。名前・部屋作成・コード参加・CPU戦を1画面にまとめています。ゲーム中の上部に「所持G / 確保済み」、金庫の下に今回の未確保額を表示し、右側に参加者の名前・状態・所持Gを大きく表示します。

お宝一覧は小型→中型→大型の順にグループ化し、各グループ内は金額順です。共有品は最初に出現する金庫に一度だけ掲載します。遊び方・お宝一覧・リザルトは外側の暗い部分を押して閉じられます。内容の内側を押しても閉じません。

ラウンド終了ごとと5ラウンド終了時に、全員の順位・今回獲得G・合計Gをリザルト表示します。同点は同順位（例：1位・1位・3位）。自分の行を強調し、ホストはリザルトから次のラウンドや再戦を開始できます。閉じた後は参加者欄の「全員のリザルトを見る」から再表示できます。リザルト表示はクライアント側で計算するため、進行中の部屋を維持したまま画面更新できます。

探索・脱出の操作バーと残り時間は画面下に固定しています。PCでもスマホでも、開始直後にスクロールせず操作できます。操作バーは金庫のクリップ領域の外に置き、実際の高さと端末のセーフエリアに応じた余白をページ下部に確保しています。

金庫パネルと右側のプレイヤー・履歴欄は上端でそろえ、それぞれ内容に合った高さで表示します。右側の履歴が増えても、金庫の指標の下に空白を追加しません。ボタン・メニュー・ロゴのクリックにはWeb Audioの短い操作音を付け、決定系は明るい2音にしています。ヘッダーの0〜100%スライダーでBGM・操作音・ぷちゅんを一括調整し、設定をブラウザに保存します。

「ぷちゅん」暗転はDPRだけで発生し、レアとレジェンダリーでは発生しません。効果音は初期状態ON、40%音量です。ゲーム開始後は `assets/heist-music.mp3` を18%音量でループ再生し、ぷちゅん中は一時的に小さくします。音OFFとホーム復帰で停止します。

## Web公開

本番環境はCloudflare Workers＋Durable Objectsです。1部屋を1つのDurable Objectが担当し、対戦状態をSQLiteストレージへ保存します。参加者の同期にはHibernation対応WebSocket、20秒の制限時間とカード公開にはDurable Object Alarmsを使います。静的画像・音声・UIはWorkers Static Assetsから配信します。

1. `npm install`
2. `npm run cf:dev` でローカルCloudflare環境を起動
3. `npm run cf:deploy` で公開

`qa/cloudflare-smoke.mjs` は、2人の部屋作成・参加・WebSocket同期・ラウンド完走を確認します。従来のNodeサーバーもWebSocket対応で残してあり、`npm start` で起動できます。Node版の部屋はメモリ保存のため、サーバー再起動で消えます。

公開URLを共有し、1人が部屋を作成して金庫パネル上部に表示される数字4桁の部屋コードを送ると、別端末から最大8人まで参加できます。コード表示を押すと招待リンクをコピーできます。`/healthz` で稼働状態を確認できます。

`qa/rare-playthrough.mjs` はレア演出のブラウザ確認専用プリロードです。通常起動では使用しません。演出の進行・キャンセル・短縮表示は `rare-effect.test.mjs` で検証します。
